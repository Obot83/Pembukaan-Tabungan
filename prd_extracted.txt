Executive Summary & Latar Belakang
Tujuan Dokumen
PRD ini mendefinisikan kebutuhan modul Pembukaan Tabungan pada aplikasi E-Collect yang digunakan Petugas Lapangan/Collection BPR untuk membuka tabungan secara jemput bola oleh petugas collection.
E-Collect difokuskan pada capture dan inisiasi proses. Kompleksitas KYC, CIF, approval, penerbitan rekening, dan posting transaksi tetap berada pada CBS/Back Office.
Latar Belakang
Petugas perlu melakukan pembukaan rekening di lokasi nasabah seperti pasar tanpa membawa proses administrasi CBS ke lapangan.
Input manual yang terlalu banyak meningkatkan waktu dan risiko kesalahan.
Data identitas dapat dipercepat melalui OCR e-KTP, sedangkan tanda tangan dilakukan langsung oleh nasabah menggunakan stylus.

Detail Alur Proses Pembukaan Tabungan

	

	Gambar 1 Flow Pembukaan Tabungan

	Penjelasan:

	Petugas Lapangan (E-Collect Mobile)

	Proses dimulai di sisi petugas lapangan menggunakan aplikasi mobile: 

	Inisiasi & Input: Petugas memilih menu Buka Tabungan Baru, memilih produk tabungan, serta memasukkan nomor handphone nasabah. 

	Akuisisi Data Identitas: Melakukan pengambilan foto e-KTP melalui kamera, yang langsung diekstrak datanya menggunakan teknologi OCR (Optical Character Recognition). 

	Koreksi & Konfirmasi: Petugas meninjau serta mengoreksi data hasil OCR jika diperlukan, mengambil tanda tangan digital nasabah (menggunakan stylus), dan menginput nominal setoran awal. 

	Review & Submit: Seluruh data nasabah, produk, setoran awal, dokumen, serta tanda tangan diperiksa kembali pada halaman Review Data sebelum disubmit. 

	Tagging Lokasi: Saat proses Submit Pengajuan, sistem aplikasi otomatis merekam metadata GPS & Timestamp. Status transaksi di aplikasi E-Collect berubah menjadi PENDING APPROVAL. 

	TOP Operator - E-Collect (MongoDB)

	Layer ini bertindak sebagai middleware backend / penampung data operasional: 

	Terima Pengajuan: Sistem menerima payload pengajuan, memvalidasi data, lalu menyimpan file dokumen serta menetapkan status awal PENDING APPROVAL. 

	Database MongoDB: Menyimpan data pengajuan secara terstruktur/dokumen, meliputi: data pengajuan, hasil OCR, gambar tanda tangan (signature image), nominal setoran awal, GPS & timestamp, serta audit log transaksi. 

	Data pengajuan kemudian diteruskan ke layer integrasi untuk diproses ke CBS. 

	Integration / API

	Layer integrasi bertindak sebagai jembatan penghubung antara sistem E-Collect dan Core Banking: 

	Tugas Utama: Melakukan pemetaan data (data mapping), transformasi data, validasi format agar sesuai spesifikasi CBS, pengiriman request ke CBS, serta penanganan respon (response handling). 

	Meneruskan status akhir (berupa nomor rekening atau alasan penolakan) dari CBS kembali ke sistem E-Collect. 

	CBS / Back Office (MySQL) & Teller / Verifikator

	Merupakan sistem perbankan inti tempat validasi akhir dan eksekusi transaksi akuntansi dilakukan: 

	Verifikasi Data: Verifikator/Teller melakukan pengecekan kepatuhan (KYC & CIF), verifikasi keabsahan dokumen, serta pengecekan duplikasi akun. 

	Approval / Decision Point (Hasil Verifikasi?):

Jalur Approve:

Generate No. Rekening: Akun resmi dibuat di CBS, setoran awal otomatis diposting (ledger posting), dan SMS notifikasi dipicu ke nasabah. 

Kirim Notifikasi ke E-Collect: Mengirim status APPROVED, nomor rekening, dan informasi rekening aktif. 

Sinkronisasi Balik: Data di MongoDB dan status di aplikasi mobile diperbarui menjadi APPROVED + No. Rekening, setoran terposting, dan proses Rekening Aktif (Selesai). 

Jalur Reject:

Penolakan: Status ditetapkan REJECTED beserta alasan penolakan, tanpa penerbitan rekening. 

Kirim Notifikasi ke E-Collect: Memberikan informasi status penolakan dan alasannya. 

Sinkronisasi Balik: Database MongoDB dan aplikasi mobile mencatat status REJECTED + Alasan, dan alur berakhir pada status Selesai (Gagal).
