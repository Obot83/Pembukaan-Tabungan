2. Tujuan Dokumen
Dokumen ini menerjemahkan baseline PRD terbaru menjadi desain teknis untuk collection MongoDB, penyimpanan dokumen S3, REST API E-Collect, dan kontrak integrasi CBS. Struktur data dan API mengikuti flow terbaru: Produk & Kontak → Foto e-KTP → OCR KTP → Data Tambahan → Alamat KTP → Alamat Domisili → Tanda Tangan → Setoran Awal → Review & Submit → Pending Approval → Verifikasi CBS → Approve/Reject → Rekening Aktif.
Dokumen menjadi acuan FSD/TSD dan implementasi. Detail endpoint final CBS, authentication, timeout, queue, deployment, serta mapping field final tetap dikunci bersama tim CBS/vendor.
3. Prinsip Arsitektur Data
CBS adalah System of Record untuk Master Product Tabungan, CIF/KYC, verifikasi, rekening, dan transaksi.
TOP Operator/E-Collect adalah System of Record untuk lifecycle aplikasi E-Collect, status history, audit aplikasi, dan metadata dokumen.
Master Product Tabungan tidak dibuat ulang di MongoDB; E-Collect mengambilnya dari CBS melalui API/integration.
Master user menggunakan master_users TOP Operator yang sudah ada; application menyimpan user_id dan snapshot actor.
Foto e-KTP dan signature disimpan sebagai binary object pada private S3; MongoDB menyimpan metadata/object_key.
Data OCR dapat dikoreksi petugas; perubahan hasil OCR harus tercatat pada audit log.
Setoran awal dicatat di E-Collect; posting transaksi dilakukan oleh CBS setelah rekening berhasil dibuat.
Alamat KTP dan alamat domisili disimpan terpisah; domicile.same_as_ktp digunakan untuk menandai apakah data domisili mengikuti KTP.
Mobile tidak mengakses MongoDB/CBS secara langsung; semua akses melalui TOP Operator API.
reference_no dan Idempotency-Key digunakan untuk mencegah duplicate submission/posting.
Data sensitif dilindungi melalui authentication, authorization, encryption, access logging, retention, dan audit trail.

39. End-to-End Sequence
1. Mobile → TOP API: GET active savings products.
2. TOP API → CBS: GET product master → return product list.
3. Mobile → TOP API: Create DRAFT with product/contact.
4. Mobile → TOP API: Upload KTP → TOP stores KTP in S3.
5. Mobile → TOP API: OCR KTP → return OCR fields.
6. Mobile: Petugas review/correction OCR.
7. Mobile → TOP API: Save additional customer data.
8. Mobile → TOP API: Save address KTP and domicile.
9. Mobile → TOP API: Upload signature → S3.
10. Mobile → TOP API: Save initial deposit + fund source.
11. Mobile → TOP API: Save GPS.
12. Mobile: Review & Submit.
13. TOP API → MongoDB: update SUBMITTED/PENDING_APPROVAL.
14. TOP API → CBS: submit complete application.
15. CBS: verification/KYC/CIF/duplicate/product validation.
16. CBS → TOP API: callback APPROVED/REJECTED.
17. TOP API → MongoDB: update status/history/audit.
18. Mobile → TOP API: Get status/history.
19. If APPROVED: CBS creates account / returns account number.
20. CBS/TOP: initial deposit posting according to agreed integration.
21. CBS/TOP: transaction result.
22. TOP → Mobile: ACCOUNT_ACTIVE + account number, or REJECTED + reason.
40. Idempotency, Retry & Resilience
reference_no immutable dan unique.
Submit dengan reference yang sama tidak membuat application kedua.
Initial Deposit Posting menggunakan unique transaction/reference key untuk mencegah double posting.
Timeout CBS tidak otomatis berarti REJECTED; status tetap pending/processing sampai hasil pasti.
Retry hanya untuk technical/retryable errors, bukan business rejection.
CBS callback idempotent; callback duplikat tidak menggandakan perubahan.
Semua integration request memakai correlation/request ID.
